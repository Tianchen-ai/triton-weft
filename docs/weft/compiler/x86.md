# x86 compilation

The x86 backend compiles the same Canonical language to SIMD and Intel AMX.
Authors can choose x86-specific blocking and persistent layouts in ordinary DSL
programs; the compiler implements their typed operations and relationships.

## Pipeline

| Area | Responsibility |
|---|---|
| Conversion | Import Canonical shapes, fields, control and storage into the physical program |
| Arithmetic | Integer reductions, finite-width proofs, lookups and floating operations |
| Memory | Packetization, array forwarding, snapshots, indexed values and streaming stores |
| Contraction | Vector/VNNI or AMX selection, operands, transfers and accumulator handling |
| Control | Full tiles, reduction schedules, projections and software pipelines |
| Resources | Live vector/fragment pressure and invocation-local storage |
| Emission | LLVM conversion, IR translation and native code generation |

`Target/X86/IR/Dialects.cpp` registers the upstream MLIR dialects used by this
physical representation. Target-specific behavior lives in these passes and
capability contracts.

## SIMD and matrix programs

AVX2 and AVX-512 targets supply different SIMD widths and register capabilities.
An explicit `engine="vector"` permits SIMD and VNNI realizations.
`engine="matrix"` requires a legal matrix realization for the declared types.
INT8 and BF16 contractions can use AMX when their complete numerical and operand
contracts are supported.

For AMX, local packing and accumulator transfers are explicit physical work.
The runtime handles OS tile-state permission for artifacts that require it.
The [contraction example](../getting-started/examples.md) prints actual artifact
extensions so the selected path is visible.

## Inspect and tune

Use `compiled.asm["x86ir"]` for the physical program and `["llir"]` for LLVM IR.
Source block sizes belong in `triton.Config.kwargs`; shared options such as
`pipeline_depth` belong in `backend_options`. Target-specific options are validated
by the CPU backend.

Compare generated code and its native workload with GGML or an explicitly selected
library using [Bench](../experiments/reproduce.md). The detailed
[x86 specification](https://github.com/Tianchen-ai/triton-weft/blob/main/docs/specification/compiler/x86.md)
records packet, AMX, alias, resource and scheduling contracts.
