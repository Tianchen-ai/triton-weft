# x86 native compilation

The Weft model uses the same Triton frontend, JITFunction, specialization, cache,
autotuner and native artifact interface on RISC-V and x86-64. Target selection
does not change the meaning of a program or replace the process's GPU driver.

```text
Shared Triton CodeGenerator
  → Canonical Kernel IR
  → x86 physical module: vectors/arrays, masks, memory and SSA control
  → LLVM IR
  → Clang / LLVM x86 code generation
  → native kernel and the shared OpenMP launcher
```

RISC-V continues to use its own Physical IR and intrinsic C/local asm emitter.
The x86 compiler does not import that emitter, reinterpret RVV layouts, or call
GGML, OpenBLAS or oneDNN to implement a kernel. Those libraries can be references
in the independent Bench.

## Target and execution contract

An explicit target is `CPUTarget("weft", "x86_64", "x86-64-v3", "sysv", 0)`
or the `x86-64-v4` variant. These select AVX2 or AVX-512 respectively. `vlen_bits`
is zero because it describes RVV's runtime vector length, not x86 register size.
The target's `vector_bits` capability is 256 or 512.
`register_file` reports architectural capacity: 16 vector registers for the v3
profile, 32 for v4, and seven usable predication registers for v4. These facts
are distinct from a program's live values and from LLVM's final allocation.
Optional ISA features are explicit suffixes, for example
`x86-64-v3+avxvnni` or `x86-64-v4+avx512vnni`. `avx512vnni` requires the v4
profile. The optional `avx512vbmi`, `avx512vbmi2` and `avx512fp16` suffixes also
require v4 and enable byte permutations, bit operations and half-precision
conversion respectively. Unknown, duplicate or incompatible suffixes are errors. Discovery
intersects these capabilities over the allowed CPU set. The complete feature
set participates in artifact loading and worker checks, LLVM function attributes
and the native compiler command. A vector-width check alone does not authorize
an optional instruction. Toolchain flags cannot silently enable undeclared ISA.

The x86 `backend_options` field `tune_cpu` selects an LLVM x86 scheduling model,
for example `"sapphirerapids"`. It is separate from the ISA target: LLVM retains
the declared `target-cpu` and `target-features` and receives the selected model
as `tune-cpu`. An empty value keeps the target's default scheduling model;
unknown names are errors. This option participates in Triton's compilation cache
and exported metadata. It cannot authorize instructions absent from the target
or relax worker capability checks, and requires no vendor-specific kernel path.

Native discovery inspects every CPU in the calling thread's allowed affinity,
restores that affinity, and selects the strongest supported common target. It
uses LLVM's CPU feature probe, including OSXSAVE/XGETBV state availability.
Loading checks the artifact's architecture, ABI and complete feature contract.
Each executing worker must remain in the discovered CPU set and retain enabled
vector state. The runtime never silently changes an application's affinity or
falls back to another ISA.

An explicit `x86-64-v4+amx-tile+amx-bf16` target admits BF16 matrix instructions.
The `amx-int8` feature admits signed and unsigned byte matrix products with
wrapping I32 accumulation. Both arithmetic features require `amx-tile`.
Discovery reports these available matrix capabilities separately from the default
SIMD JIT profile. Each executing worker obtains and verifies Linux XTILEDATA
permission before calling an artifact that uses AMX. Capability discovery does
not acquire that permission, change affinity or establish execution evidence.

## Physical program and lowering

`weft-bind-source-parameters` first validates the author's finite `auto` domains
and selects one concrete value per parameter on a candidate copy of Canonical IR.
RISC-V and x86 share this target-independent pass; it has no layout, ISA or cost
inputs. Missing or out-of-domain bindings are errors. A declared singleton is
already a complete choice.

`weft-convert-to-x86` consumes the specialized Canonical operations and emits one
target-aware physical module. It uses standard MLIR `arith`, `math`, `vector`,
`scf`, `func`, `memref` and LLVM memory operations, with the target and typed ABI attached
to the module/function. A separate custom dialect is not needed for operations
whose entire physical contract is already expressible by these dialects.

Logical axis identities determine broadcasting, permutation and contraction
before numeric values become flat fixed vectors or runtime-sized arrays. Reshape's axis permutation
preserves coordinates. Ordinary control preserves its SSA carries. Reduction
and scan trees belong to the closed primitive; they do not introduce source
state or change the author's visible reduction boundaries.

Memory masks control the actual LLVM masked load/gather/store/scatter, or a
scalar guarded access. A proven unit-stride relation selects a contiguous
transfer. Other offsets retain their individual addresses, including narrow
integer wrap before pointer-width extension. No inbounds or alignment promise
is inferred from common input shapes. Boolean storage uses one byte per element;
numeric predicate vectors use i1 internally.

View stores accept Triton's `cache_modifier=".cs"` streaming hint. The x86
physical store pass selects non-temporal packets only for a checked, disjoint,
write-only F32 output whose complete store set has the hint. Mixed ordinary
writes, indexed scatter, escaping output pointers and shared alias groups keep
ordinary stores. Runtime alignment selects 512-, 256- or 128-bit packets within
the declared ISA. A partial mask or an address below the required packet
alignment retains the original masked access, with a store fence before it;
function return also fences outstanding streaming writes. The hint never
permits a wider memory footprint or changes the lifetime of input snapshots.
Pointer expressions retain per-axis address relations through broadcasting and
insertion or removal of unit dimensions. A unit-stride inner axis can use
separate native packets even when rows have gaps. With pointer-width arithmetic,
the relation can be proved statically. With narrower arithmetic, the physical
program compares every extended offset with the proposed contiguous sequence
before choosing that transfer; otherwise it uses the original individual
addresses. Both paths keep the original mask and fill. Wrapping before extension
is never assumed absent.
A tile's maximal proven contiguous suffix selects unit-stride row packets even
when its leading dimension contains gaps. Each packet retains its own mask;
this does not assert that the whole flattened tile is contiguous. Validity is
computed on each independent logical axis and projected to the physical lanes.
For a declared runtime stride, the physical program can test whether the inner
stride equals one and select contiguous row packets. Other stride values retain
the original indexed addresses. Both paths use the same masks and unaligned
access contract; the check does not specialize the JIT cache or change the View ABI.
If a dynamic-stride tile's complete address and payload vectors would each exceed
the target's vector register file, a non-unit-stride load uses bounded native row
helpers. Stores consume their payload immediately: each explicit address packet
is bounded by both target vector width and the proven row boundary, and is used
by its masked store in the same function. They do not call row helpers that would
clobber registers holding the remaining payload. A register-resident tile keeps
its existing inline transfer.
Each helper forms its addresses from a scalar row origin and the declared inner
stride, and retains the exact payload, per-lane mask and load fill. Keeping that
address expansion inside a non-inlined helper prevents the alternate branch's
large address vectors from staying live across the surrounding computation.
The contiguous branch still emits direct row transfers. This changes neither
the accessed coordinates nor snapshot/effect ordering and adds no source storage.
BF16 helper parameters and results use exact I16 carriers. Generated row helpers
preserve tile state, so they do not interrupt AMX configuration reuse around a
traversal; arbitrary native calls still require their own verified contract.
An encoded snapshot compares complete record coordinates before broadcasting
validity to its bytes, preserving the rule that a partial record is inactive.
BF16 memory accesses use exact i16 payloads before restoring the numeric type.
This keeps masked gather/scatter legalization from introducing a float-to-BF16
runtime conversion for a program that only loads, stores or widens those bits.
BF16 widening to F32 constructs the exact high-half bit pattern using integer
extension and shift, including through contraction shuffles; F64 widening then
extends that F32 value. It does not require a BF16 conversion runtime library.
F32 narrowing to BF16 uses integer bit operations for round-to-nearest-even or
toward-zero as declared. Ties use the retained low bit; signed zero, subnormal
values, overflow and infinities retain their conversion policy. NaNs remain NaNs
with a quiet payload. The same rule handles scalar and vector carriers without
requiring a target BF16 instruction or a conversion runtime library.

One-consumer, same-block floating mul/add can form an explicit `math.fma`, under
the shared numerical contract. Contiguous reshaping or axis renaming between
the multiply and add is transparent when every intermediate has one consumer
and the physical lane order and element type are unchanged. Fusion does not
cross a cast or lifecycle boundary.
Explicit narrowing retains its rounding mode; wrap conversions and signedness
remain visible to LLVM. Min/max that suppress NaNs and propagating
minimum/maximum retain distinct operations.

`weft-x86-expand-transcendentals` materializes f32 exponential using the matched
MLIR SDK's polynomial approximation. Low inputs are rescaled before expansion
and restored with an exact power of two, preserving subnormal outputs; overflow
and NaN are handled explicitly. This prevents vector exponentials from becoming
one scalar library call per lane. FP32-to-FP16 narrowing selects F16C packets
with the declared rounding immediate instead of relying on a wide constrained
LLVM conversion. These are local physical choices, not changes to the source
program or its tolerance. Dynamic rounding uses native-width SSE, AVX or AVX-512
packets and reads MXCSR. Defined F32-to-integer results from 2 through 16 bits can
use one rounded I32 conversion followed by the declared truncation, with any
requested saturation applied first. Boolean conversion retains its own semantics.
Without AVX-512 FP16, scalar FP16 widening on AVX-512 defines its conversion carrier with a word
broadcast. This avoids an undefined upper carrier acquiring a false dependency
on a live accumulator through a partial register insertion. Only the original
half element is read, and widening preserves subnormals, signed zero and infinities.
With the FP16 feature declared, an existing scalar widening remains ordinary
arithmetic for LLVM to select and schedule. It needs no synthetic vector carrier
or additional merge register. Only a packed conversion split into independent
scalars below uses an explicit scalar intrinsic with a defined merge source;
the unused input lanes require no initialization. Both forms read only the
declared half element and preserve rounding and exception behavior.
`weft-x86-legalize-half-carriers` also closes a two-element conversion whose
constant lane selection combines two independent scalar read snapshots. When all
users are fixed scalar projections and AVX-512 FP16 is available, it widens only
the demanded scalars at the original conversion point. The independent native
conversion chains avoid a packed insert/convert/extract dependency; no consumer
requires that packed result. Otherwise, with F16C it inserts their exact I16 bits into a completely defined machine carrier,
converts one packed group and projects the two demanded results. Targets without
that transfer widen the demanded scalars individually. Undefined upper lanes
cannot acquire an accumulator dependency. Projections from one snapshot retain
their existing packed conversion. Reads, narrowing boundaries and
per-lane validity stay in place; both F32 and F64 results preserve the half value.

`weft-x86-expand-projection-loops` exposes constant local indices in pure SSA
loops with a proven unsigned upper bound, at most four iterations, and a bounded
expanded operation count. Nested guards preserve zero/partial domains and carry
updates. Effectful memory traversal and loops without a finite proof remain loops.
`weft-x86-separate-full-tiles` uses the common `separateFullTiles` transform,
also consumed by the RISC-V scheduling pipeline. It splits a zero-based, constant-step loop
into complete iterations and its original masked remainder. A nonnegative split
point preserves empty domains. The remainder consumes the complete loop's SSA
carries, so effects, lifecycle births and accumulation order remain unchanged.
Original loops are visited inside-out. A per-function bound on cloned operations
allows parent-axis predicates to disappear inside nested compute loops without
unbounded duplication; cloned loops are not recursively reconsidered.
Once an entire nest has a complete-domain version, its original masked alternate
is not peeled again. Independent nests still use the remaining shared budget;
the original remainder preserves every tail predicate and carry.
A proposal must remove structured conditions, shaped predicate work or storage
operations without increasing the other classes. Folding scalar extent arithmetic
alone does not justify another copy of the numerical body.
Carry type alone does not exclude a loop: a scalar sum may consume a large SIMD
body. Complete-tile proofs and the shared code-size bound govern the split.
Only predicates and minimum extents proved from `upper - induction >= step`
are simplified in the complete body. This removes repeated tail checks without
asserting that runtime dimensions are divisible by a tile or enlarging accesses.
The proof also propagates through dependent View extent clips after a Level
minimum becomes constant. These clips are simplified to a fixed point before
the original complete-loop bound is discarded; remainder masks stay intact.
The cloning budget charges the simplified complete body. Boolean mask reductions
and known branches are folded on a bounded proposal before it is accepted, so a
large unreachable alternative does not consume the entire budget. The original
masked body becomes the remainder and consumes the complete loop's final carries.
Each function's allowance uses its original operation count, with a 6000-operation
minimum policy and a 24000-operation absolute cap. A proposal is also bounded
before simplification. This gives composed kernels room proportional to their
existing program while bounding nested duplication. Physical function attributes
record the allowance and added operations; neither is an estimate of runtime
instruction count or permission to change a source traversal.
Independent nested tile domains whose bounds are available at entry can share
one complete-domain version. Its entry predicate checks nonnegative bounds and
divisibility, then removes only the corresponding complete-tile predicates.
The alternate keeps the original masked traversal, carries and effects. Its
inner loops may still use ordinary complete/remainder splitting within the same
code-size allowance. Aligned subwindow offsets participate in the bound proof;
no source access is enlarged by the complete-domain guard.
`weft-x86-coalesce-vector-projections` then replaces complete constant-index
extract/insert reconstructions with a shuffle of the same SSA snapshot. Payload
and validity are proven independently; incomplete updates and dynamic indices
retain their original operations. BF16 permutations use exact i16 bit carriers.
`weft-x86-slice-snapshot-loads` partitions a masked read when all direct
consumers select known lane ranges. Overlapping ranges share one read; adjacent
scalar ranges can share a 128-bit packet. Vector fields keep their own starting
address rather than absorbing a scalar prefix. Reads stay at the original snapshot
point with their original per-lane mask and fill. Unknown consumers prevent the
transformation, and the original complete read is removed rather than duplicated.
When all consumers replicate each demanded element across a native SIMD packet,
the pass retains one scalar snapshot per element and constructs packet broadcasts.
LLVM can then use memory-broadcast operands without holding a wide source vector
and shuffling each scalar out of it. Reads retain their original snapshot point,
element masks and fill; they are never moved across writes to the backing storage.

`weft-x86-select-integer-products` runs after physical packet projection.
An unsigned byte-range product with a small constant multiplier, shifted right
by eight, can use AVX-512 byte comparisons at `ceil(256*j/factor)`.
The bounded choice admits factors at most four; powers of two keep their direct
shift. It preserves the exact high byte and subsequent finite-width narrowing,
without adding storage access or changing a reduction boundary.
`weft-x86-select-integer-reductions` recognizes i32 sum-of-products with explicit
integer widening. Signed-word pair multiplication is legal only when both input
ranges fit signed i16; its i32 wrap agrees with the declared accumulation. The
unsigned-byte/signed-byte instruction is selected only when the declared type
ranges or proven unsigned payload bounds establish that its intermediate i16 pair
sum cannot saturate. Constant masks, unsigned widening, narrowing and pure lane
permutations can establish a narrower bound. A byte lookup into a bounded saved
table retains that bound, including its zero fill; unknown input data retains its full
declared range. Both the negative and positive pair limits must fit. Other
ranges keep ordinary integer arithmetic. Inactive terms and physical packet
padding contribute zero before pair multiplication, without changing the source
reduction boundary. The selected intrinsic appears in the physical module;
LLVM translation does not choose a different numerical operation.
On a declared VNNI target, four adjacent U8×I8 products use the non-saturating
byte dot instruction with I32 accumulation. Signed-byte operands use an explicit
unsigned bias and exact I32 correction, including -128. A range proof can establish
that a wider source value fits a byte, or that one U8 operand fits signed I8;
the source dtype alone does not determine the machine operand width. Four-element
`mac_groups` can use this I32 computation for a narrower modular source result.
The target restores that result width before any later source conversion. Without
a legal byte dot, the same grouped operation uses exact signed-word pairs, or
unsigned-byte/signed-byte pairs when their saturation is proved unreachable.
The same selection serves closed I32 product reductions. Input
validity zeros inactive terms before the instruction, packet padding remains
inactive, and grouped validity is the OR of the original terms. An immediately
consumed modular I32 addition can become the intrinsic accumulator, including
complete packet assemblies, without crossing a conversion or source boundary.
The same accumulator folding selects the non-saturating signed-word VNNI form
for an immediately consumed signed-word pair product. The selected target must
support that packet width; other targets retain their existing pair instruction
and modular addition. Masks and packet assembly remain part of the proof.
The shared `Weft/Analysis/IntegerFacts` interpreter owns interval arithmetic,
signedness, conversion and product-sum overflow proofs. Canonical/arithmetic
operations and target descriptions use the same transfer rules; x86 descriptions
only explain selected intrinsic semantics. Queries are bounded to 16 levels and
512 visits, memoize within that query, and retain no facts across IR rewrites.
Unsupported widths (currently 63 bits and above), unknown producers and possible
wrap do not establish a narrower interval. Selected shuffle operands preserve
their range without importing an unused poison operand. Byte-shuffle lookup
instructions preserve the requested signed or unsigned interpretation of the
table, unioned with zero for their masked-byte behavior. They do not force a
signed codebook through an unsigned range before proving a pair product.
A narrow-then-widen pair
is removed only when this proof establishes that the intermediate source domain
contains the entire result; otherwise the narrowing remains observable.
The same exact selection applies to aligned `mac_pairs` with a retained grouped
axis. Validity is intersected before multiplication and paired with OR for the
result; physical padding contributes zero. Predicate operands widen as zero or
one. A wrapping U8×I8→I16 pair cannot use the saturating byte instruction when
its declared domain exceeds I16, even if a particular input happens to be small.
Larger even integer groups compose the same exact machine pairs or quads with
a balanced I32 addition tree inside each original group. An odd number of
partials uses a zero, inactive partner at that tree level. The compiler restores
the author's narrower modular result before any following source operation;
it does not move a widening, scale, floating conversion or reduction boundary.
This selection shares the ordinary static element-issue budget.
`sum_pairs` of signed I16 or narrower, or unsigned inputs fitting signed I16,
can use word pair multiplication with an exact constant-one operand. Invalid
terms are zeroed before the instruction and result validity remains the pair's
OR. Wider unsigned values retain their original widening and addition.
Closed sums of explicitly widened bytes can use unsigned byte sums against zero
through PSADBW. Signed bytes are masked first, biased into unsigned storage, and
corrected by the exact number of original lanes; packet padding adds no bias.
The final integer narrowing preserves the declared modular sum, including overflow.
Row projections of a shared widening retain this selection: the pass projects
the original byte snapshot and its validity before summing. It does not need to
expand every row into dwords or change which lanes belong to each reduction.
When independent same-width integer reductions form one result vector, this
pass can keep the free axis in SIMD lanes using four-output horizontal-add
trees. Each producer is first reduced to at most one 256-bit packet near its
definition; four such packets are combined within the x86 128-bit lane
topology. This avoids scalar extraction and rebuilding without extending every
partial to the final assembly point. The rule requires single-use reductions
in one block, power-of-two domains and bounded packet counts. Each output is
still its original modular i32 sum: scales, casts, validity and lifecycle
consumers remain beyond that same reduction boundary.
`weft-x86-legalize-subbyte-projections` commutes explicit signed or unsigned
widening with a lane permutation. This lets LLVM shuffle native integer lanes
instead of reconstructing packed i2/i4 registers, while retaining the same
finite-width values and signed interpretation.
For adjacent duplicated bytes with two alternating constant right shifts, the
same pass can shift the original packed words before interleaving the fields.
The original observed-bit mask must prove that no neighboring byte contributes
to the result. This removes byte-to-word expansion and narrowing for the shift;
all reads remain the original saved SSA snapshot and the result stays I8.
`weft-x86-project-integer-expressions` follows disjoint consumer lane packets
back through pure integer casts, bit operations, comparisons and selections.
Repeated requested lanes are computed once and then broadcast. Consumers that
request the same lane set share the projected packet, including when their
output ordering or replication differs. The sum of distinct packet demands
cannot exceed the original vector length. The sum of physical SIMD packets also
cannot increase, except when every demand makes a nonuniform constant shift
uniform. Broadcasts of a producer that already fits one native register retain
that shared producer instead of repeating its expression for each consumer.
Shared arithmetic outside the selected expression remains shared. Reads stay at their
original snapshot points. The pass does not move floating operations, reductions
or memory effects, and does not change finite-width arithmetic.
Integer-to-F32 conversions expose native integer packets to this projection.
Disjoint lanes can then use their own constant bit shifts and permutations
before widening, instead of expanding a whole decoded Value to wide variable
shift carriers. The same signed or unsigned conversion remains at each lane's
original numerical boundary; no floating expression or memory effect is moved.
Wide native integer producers use their declared carrier width for this packet.
The widening conversion may produce several native float packets; it does not
force byte shifts, masks and arithmetic into four separate quarter-width issues.
Subbyte and single-register producers keep float-sized conversion packets, so
their constant bit planes can become direct byte conversions without widening
an entire mixed-plane vector first.
For unsigned fields shifted between positions inside bytes, four adjacent equal
source/destination placements can share an I32 shift. A repeated byte mask removes
cross-byte contributions. The proof bounds both fields inside their original
byte and keeps the saved input, integer narrowing and per-lane validity. Numeric
one-bit fields can therefore avoid a predicate-register conversion; unequal
placements retain their ordinary per-lane expressions. An output packet must
draw from at most one native source packet when its bytes are shuffled. Crossing
several source registers retains the existing representation, avoiding a wider
word carrier that increases permutation work and simultaneous input residency.
Byte planes joined into a native word at byte-aligned shifts retain their word
assembly, avoiding extraction and reconstruction of the same storage bits.
When a byte consumer selects complete aligned words, projection may commute
through the word-to-byte bitcast. This is profitable only when the selected
word lanes turn a nonuniform constant shift into a uniform shift. Other word
assemblies retain their existing representation, avoiding redundant conversion
and permutation work. The projection preserves every demanded storage bit.
Projected pure packets are formed at their first consumer rather than all at the
wide producer's definition. Their operands remain the saved SSA values; source
reads do not move, while independent packets need not remain live together.

After complete-tile guards simplify, integer projection runs again on the pure
producer and consumer closure of selected byte lookups and grouped integer
products, and byte or subbyte conversions to F32. This includes conversions
whose shared decoded producer becomes visible only after those guards disappear.
Selected AMX packing stores expose the same pure integer producer closure after
full-tile simplification. Products of at most 16 bits, including variable scales,
can follow disjoint consumer packets. The existing demand proof limits the total
computed lanes and shares identical packets; integer wrap, masks and saved input
snapshots remain unchanged. Wider products retain their shared representation,
apart from the existing constant-byte strength-reduction rule.
`weft-x86-project-lookup-layouts` moves complete consumer permutations to byte
lookup indices when every 128-bit table lane holds the same saved table. It
requires a closed consumer set, actual mixing between old packets and no increase
in lookup instructions. It neither reloads tables nor moves reads.
`weft-x86-merge-integer-packets` then combines compatible, single-use integer
fragments feeding one native lookup packet. The result fits one target vector,
and widened intermediates fit at most two; shared producers stay shared.

After ownership is closed, structured control becomes explicit CFG blocks in
the physical module. `weft-x86-legalize-vector-carries` keeps non-power-of-two
fixed vectors in padded power-of-two carriers across block arguments and safe
lane-wise updates. Without that representation, LLVM's cross-block register
breakdown can scalarize an otherwise vectorized accumulator. The padding is
outside the logical domain: reduction and memory boundaries retain their original
lane count, and no extra memory access, reduction term or source state is added.
Padding is not propagated through division or other operations that could add
undefined behavior or effects in the unused lanes. The LLVM translator consumes
the resulting physical control and data representation.

Runtime-sized and large static Values use explicit one-dimensional MemRefs for payload
and validity, with extents and logical origins carried in SSA. Array validity is
stored as zero/one bytes and converted to predicates at use; this permits native
contiguous transfers without confusing byte-addressed storage with packed i1
vectors. The public boolean/Encoding storage contract is unchanged. Their element
operations use the same numerical lowering as fixed vectors. Explicit
SCF traversals implement dynamic memory, projection, reshape, lookup, reduction
and contraction; they do not require specializing a runtime dimension or
rewriting the author's program into fixed tiles. Fixed Values retain the vector
path. This representation choice preserves the author's stage and tile extents;
it does not reject a large stage merely because it exceeds a fixed-vector budget.
Runtime-sized dense array memory traversals use target-width packets within each logical row
and a scalar remainder. Packets never cross leading-axis gaps, and each axis's
logical limit guards the actual external access. A complete load still materializes
its snapshot before subsequent source effects. Packed storage mappings retain
their encoding-aware traversal and are not treated as ordinary dense rows.
Statically bounded array memory traversals with a proven contiguous whole span
retain their constant-bound loops for LLVM's memory vectorizer. Multiple rows
with a proven unit innermost stride and unproved or gapped leading strides use
the same row-packet decomposition as dynamic arrays. This exposes contiguous
transfers without making a flat loop reconstruct row coordinates per element.
Row gaps, tails and the original snapshot point remain unchanged.

The owned array traversal proves each coordinate is within its logical extent.
For a dense View, an extent identical to that axis's active limit needs no further
per-element bounds comparison. A shorter active limit, encoded record or unknown
relationship retains the original mask; the View's scalar guard always remains.

`weft-x86-fold-uniform-validity` replaces a private byte-validity array by an SSA
predicate when its complete domain is initialized to that predicate before every
read. The pass also keeps a uniform vector predicate as one scalar loop carry.
A uniform initial value and a lane-uniform update establish the loop invariant;
dependent carries are checked together to a fixed point. Broadcasts, selections,
uniform shuffles and structured branches preserve this property. Unknown or
lane-varying producers retain their vector representation. Consumers recover the
original vector shape with a broadcast, preserving every memory mask and effect.
The check runs again after full-tile separation, when the complete loop and its
remainder can expose different uniformity facts.
AND/OR reduction of a nonempty uniform predicate retains that predicate. This
also closes output-validity initialization after contraction schedules simplify
their loop carries, without retaining a byte array solely for the reduction.
For a predicate lookup represented as an all-zero or all-one bitset, a proven
in-range shift followed by extraction of its low bit folds to the uniform
predicate. Unknown or potentially out-of-range shifts retain their original
representation.

The private array rewrite uses an SSA
predicate when its complete domain is initialized to that predicate before every
read. It proves coverage by a scalar traversal or matching packet/tail partition,
checks that the predicate dominates the allocation, and rejects escaping arrays
or unknown users. Indexed reads retain their mask and inactive fill. The data
snapshot and its reads stay in place; only redundant validity allocation,
stores and reloads disappear. Nonuniform tails and helper/ABI-crossing validity
arrays retain their representation.
A complete static rectangular row-packet traversal can establish the same proof:
zero-based unit row traversal, complete packet-width column traversal, the exact
`row * width + column` storage map, and a total domain equal to the allocation.
The stored predicate must be independent of both induction variables and dominate
the allocation. Reads must follow the complete outer traversal; per-row or
partial-domain predicates keep their storage.

`weft-x86-materialize-indexed-values` gives dynamically indexed subbyte vectors
and numeric vectors larger than a target register addressable private snapshots.
It stores the original SSA value once at its definition. When all indexed uses
belong to one conditional arm immediately nested in the definition's block, the
private copy can instead occur at that arm's entry, outside its inner loops.
The source read remains at its original point and the copy consumes that saved
SSA value, including after intervening source writes. Uses in different arms or
across an enclosing loop retain the definition-time copy. Subbyte bits use byte
carriers and truncate back to the declared type at reads; other numeric values
retain their payload. Signed interpretation stays at the original consumer
conversion. Predicate vectors follow the same rule. No external read is delayed
to an index use, and subsequent writes cannot change the snapshot.

`weft-x86-coalesce-indexed-packets` groups row reads from those private snapshots
after full-tile simplification. Reads must share one allocation and index vector,
follow consecutive logical index lanes, and have no intervening writes, calls or
regions. Pure address expressions may be shared at the first read; source data
is never reread. The selected packet cannot exceed one target SIMD register.
The physical program checks the actual extended coordinates against a contiguous
sequence and bounds that sequence inside the allocation before issuing a vector
load. Other coordinates keep their original scalar reads. For a proven modular
unit sequence followed only by unsigned extension and pointer-width offsets,
one scalar wrap check suffices. Narrow wrap, safe indices for inactive lanes,
source validity and exact payload bits retain their original behavior.

Rectangular fixed tiles extracted from an array snapshot use masked contiguous
row transfers when their innermost storage axis is preserved. Leading-axis
coordinates, active Level extents and original validity all constrain these
transfers; no row gap or partial encoded record becomes an active access. Other
projections retain indexed traversal. Fresh fixed results use one contiguous
load from their complete initialized physical domain rather than a loop-carried
vector assembled by dynamic insertions.

`weft-x86-packetize-arrays` processes only compiler-generated, independent
pointwise traversals into fresh output arrays. It does not vectorize author
`for/while` control or reorder pointer/atomic effects. It enumerates power-of-two
packet lengths up to the target width divided by the widest payload type. Static
domains compare complete packets and scalar-tail work; unknown domains compare
steady-state work per element without inventing a runtime size. Every width is
constructed in physical IR before comparing its actual instruction classes,
addressing, supply, constants and resource usage. The pass selects the cheapest
legal completed body, rather than the first width that fits an estimate of the
scalar body. A resource rejection leaves other widths eligible; if none improves
on the original legal scalar traversal, that traversal remains.
Unsupported body structures retain that same legal scalar representation.
Complete packets use vector arithmetic and proven unit-stride transfers;
noncontiguous reads retain gathers. The original scalar loop covers the remainder,
including domains shorter than one packet. No padding lane performs memory or
numerical work. Identical SSA extents prove that broadcast index selection and
leading-coordinate remainder calculations are unnecessary; unequal runtime
extents retain their original indexing rules.

`weft-x86-forward-array-producers` removes private numerical materializations
when every payload and validity read belongs to one matching consumer traversal
per packet/tail partition. It checks equal loop domains, linear array accesses,
matching element/vector types and complete producer/consumer order. Inputs must
be fresh, nonescaping arrays whose writes finish before the numerical producer.
The original external load therefore remains a snapshot, including when a later
source operation writes the same external storage.
Producer and consumer must also share their original Canonical block scope.
This provenance survives physical region flattening, keeping state/stage births,
Level bodies and source control regions distinct during numerical forwarding.

The pass moves each pure typed producer body once into its consumer and removes
the intermediate array stores, loads, allocations and standalone loops. It does
not duplicate a producer across independent consumers, move pointer/atomic
effects, alter author control, or change a cast or accumulator type. Escaping
arrays, unmatched traversals and shared materializations retain their storage.
The pass constructs the proposed consumer before committing the rewrite, then
analyzes its actual SSA lifetimes rather than adding independent producer and
consumer bounds. All scalar/vector partitions must pass the resource check
before any original materialization is removed.

These selections share an x86 resource analysis. It combines local last uses,
loop-carried values, direct captures and values still live across enclosing
regions. Numeric vectors and AVX-512 predicate registers have distinct budgets;
AVX2 predicates use vector carriers. Numeric casts and indexed transfers charge
their legalization scratch at use instead of an unconditional four-register
reserve. Literal constants are rematerializable, so their carriers and work are
charged at uses rather than assumed resident across every loop. This is a
physical candidate estimate; LLVM still owns final allocation and spilling.
`ub.poison` placeholders carry no saved physical bits and consume no resident
registers. Values that define lanes, loop carries, and frozen results retain
their ordinary resource charge; an unspecified input does not make its defined
consumers free.

The contraction schedulers also account for native-width instruction classes,
read/write bytes, conversions, permutations and SSA dependency paths. Integer
division by a known unsigned constant uses its shift/multiply implementation
class; arbitrary integer division charges scalar-lane work. A shared
`Analysis/PhysicalDependence` query computes both the longest local path and a
carry-to-yield path bound from the current SSA graph. These estimates are
structural units, not calibrated CPU cycles. An unpriced operation makes a cost
estimate incomplete; it does not receive a fictitious zero cost. The older
`work_units` field remains an operation-volume observation, separate from
instruction-class `issue_units`.
Integer absolute value is priced by its native width: AVX2 qwords require a
sign/xor/subtract sequence, while byte/word/dword packets and AVX-512 qwords use
native absolute value. The source's minimum-integer wrap behavior is unchanged.

Pointwise, contraction and reduction candidates share a physical loop cost:
the steady period includes issue work, the carried dependency and loop control;
known short domains also pay the initial dependency path. Packet endpoint
preparation, the scalar remainder and result merging are included for static
domains. Dynamic domains retain startup and completion costs as separate fields
instead of assuming a runtime size. A partial reduction's merge is priced from
the actual payload and predicate operations and their tree depth. Constants
defined inside a body follow the same use-site rematerialization rule as outer
constants. A broadcast or splat constant divisor retains its arithmetic class;
its vector wrapper does not turn it into an arbitrary scalarized divide.

`weft-x86-schedule-array-reductions` selects independent partials only inside a
closed array sum/min/max primitive. Its finite policy domain contains one through
eight partial copies, further bounded by the target register file. Each proposed
loop is built and analyzed with the same surrounding residency. Its score uses
that candidate's actual address, transfer and conversion work, the carry path,
loop control, partial merging and remaining packets. Output-vector reductions
with a scalar reduction step use this same bounded partial schedule.
Static short domains pay their actual merge/remainder overhead. Unknown lengths
use steady-state cost and preserve an explicit runtime remainder.

Iteration partitioning uses the ceiling trip count, including a non-aligned final
iteration. Empty and reversed signed-index domains are clamped before unsigned
distance arithmetic. Complete partial groups and the original remainder cover
each original iteration once; a group with no remainder retains the source upper
bound rather than requiring an out-of-range endpoint. Candidates whose expanded
step cannot fit the index range are excluded. Endpoint preparation is charged
once and reported separately for dynamic domains. This follows the trip-count
partitioning used by Triton's `LoopUnroll.cpp` through SCF's `loopUnrollByFactor`,
while retaining independent partial identities instead of copying an author carry.

The x86 physical passes and their dialects are registered with `triton-opt`,
`triton-reduce` and the other upstream IR tools. Their factories and interface
registration are shared with the in-process compiler, so a physical reduction or
packet schedule can be replayed without a separate lowering implementation.

Selected partials start from the primitive identity, consume disjoint packets,
merge pairwise in the same type and finish with the original packet/scalar tail.
Payload and validity accumulate independently. No author loop, seed, stage or
handoff is reassociated. Over-budget candidates are rejected before selection.
When canonicalization removes a redundant validity carry, the remaining payload
reduction uses the same candidate selection rather than losing scheduling support.
An already materialized source representation which needs spills remains LLVM's
allocation responsibility. This does not establish whole-program resource closure
or x86 contraction tile selection.

`weft-x86-schedule-array-contractions` compares target-width packets along the
reduction axis and packets of independent outputs within a closed contraction.
The latter retain the numerical reduction inside each lane, share an operand
coordinate that is invariant over those outputs, and select unit or gathered
supply from the actual address relation. A complete aligned output packet may
share the quotient of its linear index by a row extent divisible by that packet;
other row crossings retain individual addresses. The decision joins the physical
lane direction, supply work and simultaneous residency, without changing the
author's logical tile or engine.

Each candidate is constructed before selection. The resource check covers both
its reduction body and the enclosing output transfers. Cost includes preparation,
output stores, horizontal result conversion and the original scalar remainder
for known domains. Dynamic domains report steady-state per-product cost and
startup/merge costs separately; no runtime length is invented. Over-budget
choices are rejected while the other widths and lane directions remain eligible.
Scalar integer zero and floating positive zero are checked by their respective
numeric contracts before splitting the primitive's identity across lanes.
Shared Canonical axes already have equal extents, so these traversals need no
artificial extent-one broadcast select. Empty domains remain inactive. Narrow
inputs are converted before multiplication in the declared accumulator type.
The independent-partial scheduler also accepts these FMA or integer accumulators.
Only compiler-owned loops writing fresh private outputs qualify; the reduction
body must be an ordinary read epoch with no writes or unknown effects. Original
input snapshots remain at their original positions. These rules do not vectorize
an author loop or move a source read across a mutation.

Fixed floating contractions compare free-axis arithmetic/permutation work with
reduction-packet and horizontal-combine work when both operands are contiguous
along the reduction axis. They can retain that axis in SIMD lanes rather than
expand one dependent output-vector FMA per reduction element. These structural
estimates are not measured CPU cycles or global matmul layout selection.
Fixed byte-to-I32 contractions on an explicit VNNI target also compare independent
horizontal dots with four-product groups whose SIMD lanes are independent outputs.
Both candidates implement the same closed modular contraction. The latter requires
a complete four-term partition and the instruction's full signedness contract;
full U8-by-U8 remains ordinary arithmetic. Packet work, horizontal merging and
operand permutations participate in the estimate. The candidate estimates input
retirement by the actual free/reduction axis map. Shared source operands remain
resident through the last output packet; other input packets retire at their
final consumer. Each native issue uses its bounded packet scratch. Pressure
from saved inputs and completed output packets charges estimated spill and reload work
against the horizontal candidate, rather than excluding the grouped instruction
regardless of the alternative's cost. This is a local work estimate, not a
whole-program spill guarantee or LLVM allocation result.
Signed-word pair contractions use the same retirement and transfer-cost rule.
The complete result need not fit the vector register file simultaneously: that
would reject useful packet schedules even when the horizontal alternative has
the same result residency and more arithmetic.
The physical program completes one native output packet before constructing the
next packet's operands. Its bound includes the retained result packets and the
current packet's scratch, rather than keeping every packet's temporaries live
together. This partitions only the independent outputs of the closed contraction;
the source's accumulator, reduction domain and numerical boundary stay unchanged.
An operand without a varying output axis needs one packet broadcast. The cost
model charges that broadcast instead of a general permutation; equal-work
candidates prefer output accumulators over per-output horizontal trees.

For explicit AMX BF16 targets, a closed two-dimensional BF16-to-F32 contraction
can use tile instructions when its immutable row-major snapshots have a complete
32-term reduction partition. Free dimensions use complete 16-row/column tiles
or a single smaller rectangle. Physical row/column replicas use at most two
operand tiles per side and four accumulator tiles, within the eight-tile file.
The program packs adjacent BF16 pairs into contiguous B rows, configures and
loads tiles, executes the reduction, stores outputs and releases tile state.
Packing and tile transfers remain inside the invocation; no reference library
or persistent caller-side pack is inserted.

AMX flushes subnormal arithmetic. Before selecting it, the physical program
checks validity and a BF16 exponent domain that makes every product a multiple
of the smallest normal F32 value and bounds all partial sums away from overflow.
Zeros are permitted; other magnitudes, nonfinite values and masked tails retain
the ordinary F32 contraction. A private snapshot's check may be shared after
its initialization completes, within that snapshot's lifetime. It cannot read
an allocation before initialization or move an external source read. Borrowed
MemRef arguments keep tile transfers visible to ownership lowering until their
native pointer operations are emitted.

For an explicit AMX INT8 target, a closed two-dimensional contraction can use
the corresponding signed/signed, signed/unsigned, unsigned/signed or
unsigned/unsigned tile instruction. Fixed subbyte operands widen according to
their declared signedness before entering byte storage. Both input snapshots
use a reduction-last physical representation; bounded fixed snapshots may have
either logical axis order. The physical pass permutes their saved payload and
validity together, so standard `tl.dot(A[M,K], B[K,N])` retains its source layout
and masked reads. The output retains the left and right free axes in that order.
The shared `Analysis/LogicalAxes` relation validates the free and reduction axes
and their extents independently of the source order. Array snapshots may also
use either reduction-axis position. A reduction-first left snapshot is copied
into reduction-last private storage using bounded register rectangles. A
reduction-first right snapshot is interleaved directly from `[K,N]` into AMX B
rows, avoiding an intermediate full `[N,K]` copy. These are physical adaptations
of an already initialized immutable snapshot. They do not move source reads,
change Encoding, or extend an author's state lifetime. The existing validity
and BF16 numerical guards are evaluated on the original snapshots before packing.
BF16's alternate still consumes the original operands and axes; an explicit
matrix request remains an error when BF16 input values could require SIMD.
The local selection admits at least one row and column,
with complete 16-element tiles beyond the first tile, and a reduction divisible
by 16. Integer tile widths select 64, 32 or 16 terms from that divisibility;
packing and validity packets divide their actual storage domain without padded
reads. BF16 retains its complete 32-term partition. This is a finite selection policy, not a promise of profitability for
every source block size. The author still selects snapshot reuse and reduction
boundaries. In particular, many short scaled dots can cost more in packing and
result transfers than a single complete reduction.

Array and fixed-vector snapshots share the tile materializer. Byte quadruples
are packed into B's I32 words inside the invocation. The selected instructions
preserve all input values, including -128 and 255, and I32 wrap. A complete
validity predicate selects direct packing for complete array snapshots. Partial
arrays zero inactive saved lanes in their private physical packing and still
execute the same integer tile operation. Left transposition incorporates this
zeroing, and right packing incorporates it before grouping bytes. A reduction-last
left operand uses a separate private zero-filled copy, preserving other consumers.
Fixed snapshots likewise zero inactive saved input lanes.
Each result's validity is the OR of the original pairwise input validity across
its reduction domain, including disjoint masks and empty domains. This avoids
expanding another complete arithmetic program for a masked tail. Array outputs
compute the same OR of pairwise predicates in a separate bounded validity loop.
An integer array contraction can therefore honor explicit `engine="matrix"` on
both complete and partial domains. Source reads
retain their masks. No saturation or input-range assumption is introduced.
The same eight-tile resource bound used by BF16
applies to INT8 replicas.

Fixed SSA results use contiguous private storage for each hardware result tile.
The physical program projects that tile order back to the original row-major
coordinates before consumers use the value. This keeps each tile store contiguous
without changing its arithmetic, validity or logical axes. Array results retain
row-major storage, including contractions with a fixed right operand: downstream
array users consume that storage directly rather than the projected SSA result.

A fixed contraction with one integer operand from 9 through 16 bits and the
other at most 8 bits may use two byte contractions with the same complete
16-term reduction partition. The wider value is represented exactly as an unsigned low byte
plus 256 times a signed or unsigned high byte. The two I32 results are combined
with modular shift and addition. This preserves signed minima, unsigned maxima
and I32 overflow without changing source scales or accumulation boundaries.
Both wider operands and wide array snapshots retain the ordinary integer route.
A byte array on the left can also consume a fixed byte or word snapshot on the
right when the result contains at most 4096 elements. Complete saved validity
selects direct packing; partial domains zero invalid saved inputs and keep AMX.
Word decomposition keeps two private I32 results and combines them
in target-width packets after both tile computations, avoiding a wide result
held across the second computation. No source snapshot, scale or reduction
boundary moves, and arrays and fixed vectors keep their existing ownership.

`weft-x86-forward-amx-snapshots` can replace a private byte copy by direct tile
loads from the original input rows. It proves every byte's snapshot origin,
full validity, constant row geometry and uniform pointer-width row spacing.
The source must be an entry pointer, distinct from fresh private allocations;
intervening writes or unknown calls prevent forwarding. Bounded physical AMX
reduction loops may advance within the same proven rows. Author loops, partial
rows and arbitrary gathers retain their snapshots. The pass never treats a
later source value as the contents of an earlier saved read.
The same proof covers a complete two-loop private snapshot made by native row
packets. It checks the initializer's exact coverage, complete load masks, source
address dependency closure and requested tile rectangle. Only pure scalar address
operations are reconstructed; the AMX read uses the original entry storage after
the intervening-effect check. The address must be affine in the copied row and
have unit column coefficient; flattened leading-axis gaps cannot imply uniform
tile-row spacing. Constant row offsets may accompany a bounded
physical reduction induction variable. Other readers retain the private copy,
and the initializer is removed only when every consumer has been forwarded.
Byte identity can pass through contiguous vector slices, integer extension/narrowing and constant masks
that keep all eight low bits. These are bit-preservation proofs on the original
snapshot, not permission to discard a sign-changing mask or another numerical
operation. The same validity and intervening-effect checks still apply.

`weft-x86-reuse-amx-packing` reuses a private packed operand when every element
has one initialization from an invariant saved SSA value. It can move that
allocation and its integer/permutation producers before a consuming traversal,
within the original snapshot's lifetime. It moves no source reads, floating
operations or non-speculatable expressions. Escaping buffers, additional writers
and incomplete initialization retain their original materialization. Packing
remains invocation work and is never promoted to persistent model preparation.

Complete immutable packings can also be shared by dominated consumers in nested
branches. Initialization must dominate every read, every byte must have exactly
one initializer, and the address must remain nonescaping. Allocation provenance
does not imply identical coordinates: initializer bases may only pass through
identity casts. A subview can borrow the initialized storage for reads without
granting permission to reinterpret its write offsets.

For up to sixteen legal enclosing traversals, the pass recomputes the overlapping
live bytes of all packed operands under the 64 KiB residency policy. It also
analyzes the actual proposed relocation on a detached physical-function copy,
including producers' other consumers and nested-region uses. Resource pressure
is measured using the same relocation routine as the final rewrite.
Allocation, aliases, packet producers and their stores retain their original
physical order, so moving a complete initializer does not keep all prepared
packets live until its first store. Incremental vector
or predicate pressure beyond both the target budget and the original peak pays
an estimated native spill/reload round trip per original preparation. Its extra
footprint participates in the residency budget; extra pressure alone does not
discard a candidate that removes substantially more preparation work. Final
spilling remains LLVM's responsibility; this estimate does not promise the exact
spill sequence or total stack of the call chain.

Selection prices every moved integer/permutation producer and packing store at
its original and proposed execution frequency. Shared `Analysis/PhysicalDependence`
queries retain exact constant trip counts, including zero, and symbolic unknown
loop counts. Candidates on the same ancestor chain compare the leading
steady-state savings and then their finite startup term; no runtime extent is
invented. Equal work prefers smaller resource occupancy and otherwise retains
the shorter lifetime. Conditional regions have no fabricated probability and
remain boundaries. Unknown extents or escaping operands cannot supply a resource
proof. Initializers and the function's `packing_schedule` record the candidate
costs, resources and selected placement. Triton exposes this as compilation
`packing_schedules`. The records identify the pass and its invocation in the
pipeline; they are diagnostic records, never inputs to subsequent analysis. Later transfer
forwarding may remove a packing, so its selection is not proof of final runtime
execution. These are structural units, not predicted cycles. Queries and stale
decision attributes are rebuilt after motion or sharing; no cached alias/liveness
result survives a rewrite.

`weft-x86-reuse-amx-configuration` moves matching configuration/release pairs
around a structured traversal when every enclosed matrix operation has the same
configuration and no opaque call or inline assembly can change tile state.
Scalar half conversions declare their SIMD-only tile-state effect at the same
intrinsic construction site. Their typed calls therefore preserve configuration
reuse just as the equivalent ordinary floating conversion does; unknown calls
remain barriers.
Each closed contraction still initializes its accumulators and stores its result
at the original point. The pass does not carry numerical tiles across source
operations or cross an unknown native helper. Metadata records actual selected
matrix extensions, and the native SDK validates the declared features and tile
permission on the executing worker.

`weft-x86-schedule-amx-loads` schedules forwarded snapshot transfers within
one physical block after configuration reuse. It follows pure, speculatable
scalar address dependencies and crosses only independent work. Writes to external
storage, unknown calls, regions, configuration changes and uses or definitions
of the same explicit tile register stop motion. Fresh nonescaping packing
buffers may be written across this interval because they cannot alias the input.
For transfers with at least eight rows and 32 bytes per row, and no known row
spacing below a cache line, it places row-end prefetch hints before independent
work and retains the tile load at its original position. Hints name only the
final valid byte of each current proven active row, including its trailing cache
line when a row is not aligned. Smaller transfers may move the load itself earlier.
The bounded search requires at least eight independent operations; it neither
adds tile registers nor crosses iterations, creates a new source stage or
changes any numerical boundary. The physical IR records scheduled transfers.

`weft-x86-prefetch-streams` adds bounded cache hints to flat counted SIMD loops.
It accepts complete contiguous packets from read-only entry pointers and follows
only pure, speculatable scalar address dependencies. Invariant addresses and
loop-carried numerical values do not become future-iteration inputs. A positive
constant step and nonnegative start let the pass guard the lookahead using the
remaining iteration range before forming any future address. The hint names the
last valid byte of each at-most-64-byte packet at one through four iterations ahead.
Current reads retain their position; hints follow the selected current reads.
The finite policy selects the largest distance whose complete per-iteration
read footprint fits a 32 KiB lookahead budget, with at most 512 hints and 1024
unique address operations. Windows smaller than eight cache-line hint spans
retain their ordinary hardware-streamed loads: software hints would add a guard
and address work to a small existing packet. For a known finite traversal, the complete
read stream, including enclosing loops in the function, must also exceed that
budget; a few unrolled iterations do not justify another guarded address stream.
The shared execution-multiplicity analysis supplies this check. Unknown lengths remain
symbolic and keep the existing bounded lookahead. A larger author window receives a shorter
distance instead of losing all hints. Oversized windows retain their original
reads without hints. These are compiler budgets, not hardware capacities
or a CPU-cycle model. Existing matrix-tile loops keep their separate AMX transfer
schedule. Hints preserve the original loads, masks, writes, carry values and
numerical boundaries; physical metadata records the selected hint count, per-loop
read footprint, lookahead distance and address operation count.

Contiguous innermost sums and min/max keep each output's reduction domain together
rather than gather one column from every group at each tree level.
`weft-x86-materialize-reduction-trees` explicitly builds balanced vector trees
for closed floating sums and extrema. Both trees fold contiguous halves to keep
shrinking packets contiguous across x86 register boundaries. Odd sums retain
their neutral zero term, and no source carry or cast changes its boundary.
For extrema,
NaNs can be removed once before the tree and restored when no numeric input
exists. Sanitized nodes need no repeated NaN handling. A proof that the input
cannot contain negative zero permits cheaper comparisons in that tree only.
When a maximum's input also cannot contain negative infinity, its sanitized
result identifies the all-NaN case without a separate predicate reduction.
Independent F32 maxima with both proofs can combine their last four lanes in
groups of four outputs, retaining the output axis in SIMD instead of extracting
and reassembling scalars. Each original reduction keeps its own NaN decision;
partial input validity, positive infinity and positive zero remain unchanged.
Other number extrema use the same cheap numeric tree, then reconstruct a zero
result's sign from exact zero bits in the original snapshot. That work is guarded
by the final zero result; max prefers positive zero and min prefers negative zero.
NaN restoration remains independent. There are no global fast-math, no-NaN or
no-infinity assumptions. Masks and empty-domain validity remain separate.
Number extrema use quiet NaN as the inactive identity, so padding cannot turn
an all-NaN domain into an infinity. Pointwise number extrema also preserve
signed-zero ties by explicit NaN selection followed by IEEE maximum/minimum.

Closed array sum/min/max reductions use target-width lane partials, combine those
partials within the same reduction boundary and then process the scalar tail.
Strided reduction axes retain their actual address relation. Invalid elements
contribute the declared identity, and validity is OR-reduced independently.
Integer wrap, min/max NaN policy and empty-domain validity are preserved; floating
reassociation stays within the existing reduction tolerance. Numeric casts and
source state/stage boundaries are not moved into or out of the reduction.
When no logical axis survives, the result and validity remain scalar SSA values;
no one-element heap buffer is needed merely to store and reload that pair. Empty
reductions keep their inactive result, so downstream stores still skip the output.

Compilation metadata exposes `target_resources`, `array_schedules` and whether
array ownership lowering ran. Schedules distinguish packet width, estimated live
vectors and reduction partials; `forwarded-pointwise` marks an eliminated
materialization and `fusion_vector_bound` records the retained consumer budget.
`forwarded_arrays` counts removed payload/validity buffers. Resource fields expose
surrounding residency, vector/predicate peaks, scratch, and work components;
schedules record candidate counts, resource rejections and selected partial copies.
Each candidate retains its width or partial count, estimated cost, resource
components and legality decision in `array_schedules[].candidates`.
`uniform_validity_arrays` counts private validity arrays replaced by SSA predicates.
These estimates are not measured register use or
a proof that LLVM emitted no spills; inspect the native program for that claim.

For modules that allocate these arrays, MLIR's buffer-deallocation pipeline
places releases and propagates ownership through private calls and control flow.
Array descriptors, validity and extents cross helper/carry boundaries explicitly.
The four LLVM masked transfer operations expose their actual read/write effects
to ownership analysis. Intrinsic calls remain typed native calls, not pure
operations that conceal memory effects.

Before ownership lowering, `weft-x86-materialize-local-storage` gives private
BF16 buffers exact I16 payload storage, restoring BF16 only at numerical uses.
Finite-width integers use the smallest native integer carrier of at least one
byte, restoring their declared width after reads. This keeps scalar and vector
transfers consistent with element-addressed arrays: an I4 vector transfer cannot
pack two independently stored array elements into one byte. Predicate operands
of masked transfers remain I1; only the stored payload changes representation.
The representation propagates through descriptor aliases, control carries and
private helper signatures; arithmetic and explicit rounding retain their types.
This prevents array movement from introducing floating conversion library calls.

The same pass reserves bounded, nonescaping array slots at function entry under
an aggregate 64 KiB compiler stack policy. It includes existing physical stack
snapshots, prioritizes allocations nested in loops and accounts for alignment.
Constant sizes and proven unsigned bounds can reserve slots; dynamic descriptors
retain their actual logical sizes. Payload loads, stores and snapshot births
remain at their original locations. Descriptors escaping through calls, returns,
iteration boundaries or unknown users keep their ownership-managed storage. Unknown
existing stack allocation sizes prevent further promotion. Metadata reports each
function's reserved bytes and promoted allocations; it does not estimate LLVM's
later register spills or the total stack of an entire call chain.

Private arrays with disjoint lifetimes in the same physical block can reuse one
typed stack slot. The analysis follows casts, views, structured control aliases
and validated synchronous borrowed calls through the last use. Both initial and
back edges contribute to provenance. An allocation outside a loop may be borrowed
by that loop; one born inside an iteration cannot reuse one slot when a back edge
retains its address past its birth. A nested use occupies its entire enclosing
operation; escaping descriptors and different blocks cannot share a slot. A
reused slot must already have sufficient capacity, alignment and the same storage
type and memory space. Births, initialization, reads and writes remain at their
original points. The budget counts distinct slots, and `reused_stack_arrays`
records successful reuse separately from promotion.

A defined private physical helper may mark an argument `weft.borrowed` when
its lowering contract guarantees that it uses the buffer synchronously and
retains no address or descriptor. Each actual argument use is checked, including
passing the same buffer more than once. The AMX load/store leaves have this
contract, so bounded contraction buffers can occupy private stack slots across
their calls. External, unmarked and source-level helpers still require the
ordinary escape proof; a function name alone grants no borrowing contract.

Structured address propagation, alias-use closure and read-epoch traversal are
shared with RISC-V. Each target still supplies allocation/view/snapshot identity,
accepted non-retaining uses and effects. Delaying a read into a repeated region
requires the complete region to preserve the source storage, including writes
after the consumer that could affect a subsequent iteration. Conditional regions
require only the prefix containing that consumer. Opaque control stops motion.

The LLVM conversion consumes this physical program in process. It lowers CFG,
MemRef, vector, arithmetic and math operations, verifies the LLVM module, and exports
LLVM IR with a fixed target CPU. Clang is used only during native compilation.
After cache lookup or AOT loading, execution calls the already loaded library.

## Native helper functions

The common Triton frontend's `helper` regions become private native functions.
The x86 physical ABI passes the captured scalar/vector values, their logical
validity, and dense View descriptors explicitly. Descriptor offsets, strides,
bounds and origins retain their meaning across the call. An enclosing Level's
point and dynamic shape bindings are captured as explicit scalar operands;
no numerical producer or memory read is moved into the callee to recreate it.

Inside a native helper, ordinary `if`, `for`, `while` and Level control lower to
standard MLIR `cf` blocks with typed carried arguments. `helper_return` becomes
a function return, which can leave nested loops and Levels directly. State and
stage births remain ordered within each Level instance. A return skips later
effects, further instances and handoff; the caller resumes after the call.
Each reachable path must return its declared results. Missing results are an
error, never an implicit zero value.

Physical function metadata records whether the author requested `noinline`.
LLVM translation spells that decision as an internal function with `noinline`;
ordinary helper regions use `alwaysinline`, preserving source-level function
reuse without introducing a required native call. Neither path adds a launcher
or a second OpenMP team.

## Supported source boundary

The x86 entry ABI accepts ordinary Triton pointers, runtime scalars and dense or
record-encoded Views. View dimensions and explicitly declared dense element strides use the shared
native ABI; storage offsets remain in the caller's pointer. Numeric local Values
may have static or runtime shapes. Supported primitives include masked pointer memory,
broadcast and reshape, arithmetic and conversion, reductions and associative
scans, grouped MAC, pair sums, local table lookup, ordinary SSA control, pointer
atomics and dense contractions. Unsupported operations report their source
location; they do not enter a reference-library
fallback or the RISC-V compiler.

Dense View slicing, subviews and `extent` lower to explicit pointer, element
offset, bounds, stride and origin SSA values. Same-axis Level points select
absolute domain coordinates; a nested point does not add its parent base twice.
Scalar slice indices and subview offsets are relative to the selected region.
The x86 physical pass selects a unit transfer only from a proven unit stride;
other layouts keep their addresses. Runtime View validation retains the shared
capacity, alignment, writable-overlap and alias contracts.

For an entry whose memory arguments are all checked Views, an argument that is
alone in its declared alias group carries LLVM `noalias`. Shared groups retain
their permitted overlap. A mixed raw-pointer ABI or a body with raw-pointer
memory operations grants no such promise.
Read-only View access also survives translation as a parameter attribute. The
compiler does not mark a packed write as write-only: preserving neighboring bits
can require a physical read-modify-write. These facts come from the source effects
and the same alias contract checked by the native runtime.

A View load's inactive elements are a logical tail, not ordinary Triton masked
load `other` values. The physical representation carries a validity mask through
SSA control, stage, reshape, selection and state updates. Stores and pointer
effects use it to guard real memory access. Sum/min/max and contraction consume
only active elements; a tuple reduction/scan calls its combiner only when both
operands are active, preserving order without inventing a source identity. Full
domains have constant true masks that fold away. A native exported View kernel
can be called with different runtime dimensions and declared strides without
recompiling its static blocks.

Extracting a scalar does not erase that validity. Scalar arithmetic, conversions,
branch/loop carries and native helper arguments/results preserve it alongside
the payload. Pointer address arithmetic and atomic updates consume the resulting
validity just as vector effects do. Structural loop bounds and branch predicates
remain ordinary control operands; the extra fields belong to carried values,
not to the public kernel ABI.

`mac_pairs` and `mac_groups` retain the final grouped axis and combine the union
of the operands' free axes. Each selected operand is converted to the declared
`into` type before multiplication and accumulation; integer operations wrap in
that width. `sum_pairs` converts adjacent elements to i32 before adding them.
These closed operations reduce only valid terms, including partial tail groups;
an output group is active when at least one term is active. Constant vector
shuffles express grouping in the physical module without creating source loops
or changing the author's accumulator boundaries.

The input-to-output axis and group relations come from the shared
`Analysis/LogicalAxes` analysis used by RISC-V grouped arithmetic. Equal extents
do not identify axes; each operand dimension maps by its logical identity,
and a unit free dimension projects coordinate zero. The analysis does not
choose target instructions or a physical carrier.

`lookup(table, indices, bounds="in_bounds")` selects from the already computed
local table and preserves the index domain and selected entry's validity. The
table's original read is not delayed or repeated at the lookup; intervening
writes do not change that SSA snapshot. Inactive index lanes use a safe physical
coordinate before extraction and remain inactive. Active indices retain the
source in-bounds precondition, with no implicit clamp or wrap.

Small tables use native register permutations when their complete snapshot fits
the selected instruction's addressing domain. Tables of at most sixteen bytes
use independent 128-bit byte-shuffle lanes, each holding the same table. Other
elements up to 32 bits can use a full-register dword permutation, with exact
integer bit carriers for narrow and floating values. Output domains are split
into native packets and a padded final packet; padding never performs memory
access or becomes an active logical value. Table validity is selected separately.
If both the complete table and all indices fit one 256-bit issue, a 512-bit
target uses that narrower issue. Table preparation follows the same width;
unused upper result lanes do not justify a wider replicated snapshot.
Larger tables retain addressable snapshots. Selection depends on table geometry
and target capabilities, with no dependency on a codebook or kernel name.
Small predicate tables use a packed bitset and bounded shifts. This keeps a
uniform validity table visible to constant propagation, so a fully valid
lookup does not leave opaque byte-shuffle masks on its consumers. Nonuniform
validity still selects the original entry, and inactive indices retain their
safe coordinate and inactive result.

A snapshot used only by one lookup in the same Canonical block can read just its
selected entries when intervening operations have only known read effects or
no memory effects. A read used to construct the lookup indices cannot change
the saved table, even if its input aliases the table.
The indexed transfer retains the View's shape, strides, storage map, guard and
active limits. A shared/staged table, crossing a region or an intervening effect
keeps its complete saved snapshot. Contiguous groups of lookup indices can use
row transfers after checking the actual extended addresses. That check preserves
narrow-integer wrap and irregular strides; it does not assume a particular table
layout from the index expression alone.

Integer index analysis can prove a non-wrapping unit step using declared widths,
constants, widening, and bounded arithmetic/bit operations. A complete contiguous
table then uses its linear index directly; strided or partial tables keep their
coordinate and validity mapping. Unproved narrow arithmetic retains the actual
address check. No index range or alignment is inferred from observed input data.
Positive constant-bound `scf.for` induction variables also provide an interval.
Casts use that interval only when every value remains nonnegative and exactly
representable. A local projection can omit a coordinate bound check when this
analysis proves the complete index domain fits; index validity and source
snapshot validity remain independent and still guard the result.
Independent contiguous rows occupying exactly 32 or 64 bits can use word gathers
and a bit-preserving result conversion. A whole row must be active or inactive;
partial rows retain masked element accesses, without reading extra bytes.

Before storing a dynamically indexed predicate snapshot, the physical compiler
proves repeated lane expressions through pure boolean combinations and shuffle
mappings. It stores one representative for each proven group and remaps indexed
reads to that compact snapshot. Every lane must satisfy the repeated mapping;
unproved mappings retain their original storage. Producers remain at the same
snapshot point, without moving external reads or duplicating predicate arithmetic
at every indexed use.

Pointer/scalar programs can compose Level, state and stage with ordinary
control. Level becomes an ordered SCF loop with explicit carried operands and
results. Its state and stage initializers execute in separate typed regions
inside each iteration, followed by the body and handoff. Same-axis subtiles use
the nearest enclosing point's active extent, including a partial parent tile.
An empty runtime domain preserves the incoming carries without executing births.
Local Value scalar selection, gather, domain selection and element updates preserve
logical axes, including trailing axes omitted by a selector. Each local axis also
retains its logical origin through arithmetic, ordinary control and helpers.
A Level point selects coordinates relative to that origin, and its active extent
joins the existing validity mask. Parent tails and later records therefore do not
reuse the first record's coordinates or read inactive local lanes.

## Encoded storage

Record ABI metadata retains the declared byte span, logical elements, alignment
and persistent interleave identity. Natural, grouped/layered and joined fields
lower from the Encoding declaration to explicit byte-fragment maps. A fragment
specifies its byte address, bit range and numerical destination bits; the map has
no quantization formula, field-name heuristic or target-specific format identity.
Bit order and byte order remain part of that storage relation.

`Analysis/StorageBytes` owns this interpretation together with RISC-V. Its
`FieldBitLayout` describes natural, grouped/layered and joined bit spans;
`EncodingBytes` composes those spans with byte order, bit order and the declared
interleave chunks. The x86 backend consumes these proofs when choosing transfers
and decode operations. RISC-V consumes the same field facts and contiguous-bit
projection in its memory and record-loop planning. Neither query chooses an ISA
or changes persistent bytes. Continuous fields are proved from the complete
mapping formula, without enumerating the field or sampling a few coordinates.

Field descriptors carry their storage map and record geometry across helper and
control boundaries. Loads assemble the declared finite-width element. Stores
perform ordered byte updates, preserving other fields that share the same byte;
independent scatter read-modify-writes cannot replace that ordering. Full-record
loads materialize a byte snapshot at the source read, and stage/helper reuse
consumes that snapshot rather than repeating a later memory read.

Reshaping a fixed encoded snapshot maps complete logical records to their byte
spans, and applies the same byte permutation to validity. Splitting or merging
outer record dimensions therefore preserves all storage bytes even when a
record's byte size differs from its logical element count. Permuting complete
records is supported; an order that splits or permutes elements inside a record
is rejected by this backend rather than interpreted as a byte permutation.

A byte-aligned field can use ordinary numeric memory operations even when other
fields share its record. The storage fragment map must prove consecutive complete
bytes in native byte order, an integral record stride in the field's element
units, and no persistent interleave. The descriptor then carries the field offset
and record stride explicitly. Contiguous rows use masked vector transfers and
outer record gaps remain real strides. Partial records stay inactive. Subbyte,
joined, reordered or interleaved fields retain their declared storage mapping;
no field name or quantization format selects this path.
For a direct fixed field load, the compiler can materialize the declared byte
fragments as contiguous spans and SIMD bit reconstruction. Only bytes needed by
that field are read; record validity guards every span. This avoids interpreting
a storage-map table separately for each field element while preserving signed
subbyte values, joined fields and byte/bit order.

A complete cohort or a fixed number of consecutive cohorts of a declared
interleave can read field spans in physical order, then apply the same logical
projection. Each cohort retains its own base and row-validity masks, including
an inactive final cohort. A root two-dimensional View selected
by domain points provides separate row and block coordinates. A proof that the
row point is a multiple of the cohort removes the need to reconstruct those
coordinates with runtime division. Other descriptors check their actual offsets
and cohort alignment; unaligned or incomplete-cohort descriptors retain the general mapping.
The compiler never changes the author's interleave or assumes a slice is aligned.
A smaller row window can use the same field spans when it is contained in one
cohort. Each physical span adds the window's row remainder using that field
chunk's declared byte stride. Contiguous spans with different chunk strides stay
separate. Source-domain multiples can prove containment; other descriptors check
the row bounds and actual record coordinates. A window crossing the cohort keeps
the general mapping. The selected transfers access only the requested rows and
field bytes, so choosing a smaller author tile does not require changing its
persistent Encoding or reading the rest of the cohort.
A constant index on the final field axis, such as `load(tile.scales[:, group])`,
uses this same transfer proof with a one-element field window. The index may
remove that logical axis; retained record axes and their validity still determine
the cohort and byte spans. Negative, dynamic or out-of-field indices do not enter
this specialized selection, and no neighboring field bytes are added to the read.
A field store can use the same contiguous physical spans when the declaration
maps each logical I8 element to one distinct complete byte. Payload and each
element's validity are permuted together into the span; partial field windows
therefore preserve neighboring fields, padding and inactive rows. A runtime
cohort-alignment check retains the general mapping for unaligned selections.
Subbyte or shared-byte stores keep ordered read-modify-write semantics. This
selection depends only on the storage fragments and masks, not on a workspace
name or the consumer's instruction set.
An aligned, complete-record subview of that selected window retains its row
cohort and adds its declared row and record-column offsets. Nested subviews
compose these offsets only after proving each window's bounds, complete records
and complete row cohorts. A window spanning multiple
record columns must prove the complete address relation; its element count
alone cannot establish a single-column cohort.

Runtime field windows can use the same byte-span transfers when their offsets
are multiples of a fixed power-of-two window extent and the complete one-axis
field is partitioned by that extent. The storage analysis checks every window:
fragment masks, bit shifts, result shifts and interleave chunks must be identical,
and both base-record and cohort byte addresses must differ by one constant stride.
This proof is bounded to fields of at most 4096 elements. The physical conversion
then adds the runtime window's byte displacement to the selected span base;
it does not build a scalar storage-table walk for each element. Natural,
layered and joined declarations are admitted by the same fragment proof.
Ordinary dynamic single-element indices use this rule only when their whole
field has that translation property. Existing record/row/index validity still
masks real reads and writes, including partial or crossing row cohorts.
Other fragment relations retain their explicit general storage mapping.
Integer casts retain known low zero bits only within both source and destination
widths; casts do not introduce an alignment assumption.

With a predicate register file, a one-bit field whose declared fragments are
consecutive low-to-high bits can be projected as bytes and bitcast to its exact
predicate lanes. This avoids widening every bit to a word and shifting it
individually. Byte order, bit order and every fragment are verified; other layouts
keep fragment assembly. Payload bits and record validity remain independent.

Derived interleave layouts retain the author's field chunks. The same physical
mapping drives kernel accesses and native `<kernel>_<argument>_packed_size` and
`<kernel>_<argument>_pack` exports. Their LLVM code copies the declared record
bytes during artifact construction; kernel invocation does not repack inputs.
For those derived inputs, the native ABI's `artifact_pack` metadata names the base
Encoding and the exported size/pack symbols. Applications can construct a persistent
input using the same compiled layout before invoking the kernel. The input's typed
shape, record geometry, alignment and layout identity remain part of the ABI;
runtime loading does not silently convert a base buffer into a derived one.
Runtime-sized encoded snapshots use byte arrays in the base record order. Their
logical extents and origins stay in element coordinates; projection translates
the last axis to record bytes only at physical access. Field extraction uses the
same declaration-derived fragments against the saved bytes, including across
helper and stage boundaries.

Source `auto` parameters can determine static Value blocks and Level partitions.
The x86 physical conversion resolves their symbolic extents, emits their selected
constants, and records every selected binding in the native ABI. Runtime View
shape and stride parameters remain runtime arguments. Triton `Config` keyword
arguments select source parameters through the shared JIT/autotuner; selecting
another legal block compiles another candidate and does not change an existing
kernel's program or introduce x86-specific frontend syntax.
Explicit compiler `meta` selections are merged with the source's constexpr
parameters before cache lookup. Conflicting selections are rejected; zero or
negative source values reach the common legality check instead of disappearing
and being misreported as missing bindings.

A fixed vector contains at most 4096 elements (bytes for an encoded snapshot);
larger Values use arrays. This bounds LLVM vector expansion without constraining
the author's staging or local dimensions.
A statically expanded contraction
or grouped operation has at most 1048576 element issues; larger work must use author-declared tiles
and loops. These bounds control compiler expansion, not measured hardware
register residency. LLVM performs final register allocation and spilling.

Dynamic grouped/tuple reduction and scan, and matrix capabilities beyond the
BF16 contraction domain above, require their own x86 implementations. They
remain part of the shared Canonical model; selecting x86 does not erase their semantics.

Inspect `CompiledKernel.asm["weftir"]`, `asm["x86ir"]`, `asm["llir"]` and
`asm["so"]`. Exported libraries use the same single-instance and grid ABIs as
RISC-V. Single-instance callers supply their own worker partitioning; the grid
launcher uses OpenMP and checks every executing worker before writes.

## Toolchain

An x86 wheel can bundle Clang with its x86-64 code generator, resource headers
and matching OpenMP headers/runtime. Native JIT then needs no `toolchain`
argument, and exported artifacts carry the required OpenMP library. Explicitly
configured Clang remains supported. A RISC-V-only Clang cannot compile x86 LLVM IR.
`toolchain.target` must name x86-64; RVV VLEN/ABI flags are rejected. Cross-builds
still require the declared sysroot and identity. Toolchain identity and target
participate in the existing Triton cache.

Native single-instance, grid launch, Python JIT calls and model E2E retain
separate measurement boundaries in Weft Bench. An exported kernel, a correct
operator and an improved model are distinct pieces of evidence.
