# x86 编译

x86 后端将同一 Canonical 语言编译为 SIMD 与 Intel AMX。
作者可以在普通 DSL 中选择适合 x86 的 blocking 和持久布局，
编译器实现其中的 typed operation 与程序关系。

## 管线

| 模块 | 职责 |
|---|---|
| Conversion | 将 Canonical shape、字段、控制与存储导入物理程序 |
| Arithmetic | 整数归约、有限位宽证明、lookup 与浮点操作 |
| Memory | packet 化、array forwarding、快照、索引值与 streaming store |
| Contraction | vector/VNNI 或 AMX 选择、操作数、传输和 accumulator |
| Control | 完整 tile、归约调度、projection 与软件流水 |
| Resources | 活跃 vector/fragment 压力和调用局部存储 |
| Emission | LLVM conversion、IR translation 与原生代码生成 |

`Target/X86/IR/Dialects.cpp` 注册物理表示所使用的上游 MLIR 方言。
目标行为由这些 passes 与能力合同实现。

## SIMD 与矩阵程序

AVX2 和 AVX-512 提供不同的 SIMD 宽度与寄存器能力。
显式 `engine="vector"` 允许 SIMD、VNNI 实现；
`engine="matrix"` 要求声明类型存在合法矩阵实现。
INT8 和 BF16 contraction 在完整数值与操作数合同满足时可以使用 AMX。

AMX 的局部 packing 与 accumulator transfer 都是显式物理工作；
runtime 为需要 AMX 的 artifact 处理 OS tile-state 权限。
[Contraction 示例](../getting-started/examples.md)打印实际扩展，使所选路径可见。

## 查看与调优

`compiled.asm["x86ir"]` 提供物理程序，`["llir"]` 提供 LLVM IR。
Source block 大小放入 `triton.Config.kwargs`，
`pipeline_depth` 等共享选项放入 `backend_options`；
CPU backend 验证目标专属参数。

通过 [Bench](../experiments/reproduce.md)将生成代码及对应原生工作负载
与 GGML 或显式选择的库比较。
[详细 x86 规格](https://github.com/Tianchen-ai/triton-weft/blob/main/docs/specification/compiler/x86.md)
规定 packet、AMX、alias、资源与调度合同。
